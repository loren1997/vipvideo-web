# 夸克影院：目录、搜索与手动播放

“我的收藏”下方新增独立的“夸克影院”。普通影视播放页不再后台查找或转存夸克资源。夸克影院使用豆瓣官方公开目录展示电影、电视剧、动漫和综艺的海报、年份、评分和细分类别；无需配置普通影视源或评分 API 密钥。默认从热门已上映片目中按年份和评分排列，明确未上映或尚不能确认上映状态的条目不占据首页。排序针对当前已加载片目，不代表整个远端片库的全局顺序。

1. 在“夸克影院”选择分类、类型、上映年份和排序。默认热门已上映片目中，年份优先、同年高分在前，也可切换上映年份或豆瓣高分；列表没有完整首映日期时不编造日期，详情读取公开条目的真实首映信息。
2. 点开海报后按作品名称、正式别名和年份查询公开分享。电视剧和动漫先查询剧名；官方有集数时可选择当前集，再在文件列表中核对集数。
3. 手动选择分享和单个视频文件，点击“转存所选单集”。对应的外挂字幕会一起准备；转存完成后明确点击“夸克播放”，不会自动转存整个视频目录。账号仅在个人转存和播放时必需，公开目录与匿名可读取的分享可以先浏览。
4. “查找更多公开资源”继续查询后续结果，合并已验证的分享，不中断当前播放。收藏和观看历史能回到独立详情；续播按已转存文件保存，换文件从该文件自己的进度开始。

带 `#/list/share/<目录ID>` 的分享链接会直接核验和读取选定目录，普通分享仍从根目录读取。夸克不允许转存当前账号自己创建的分享，出现此提示时需选择其他人的分享来源。

豆瓣目录使用固定官方地址，列表缓存 1 小时、详情缓存 6 小时；临时读取失败时可展示保留的缓存及错误说明。公开信息可能不完整或受到访问限制，暂无评分和暂无资源会如实显示。当前已部署搜索助手的用户无需增加 YAML 或填写新凭证，只需更新现有项目镜像。

夸克功能可按影片标题和年份搜索公开分享元数据，再选择一个视频文件转存、播放。默认使用公开网页搜索；可选 PanSou 助手增加搜索渠道。分享须经夸克官方接口确认可以读取且包含视频才显示，无法读取、已取消、空目录和仅含图片的结果会隐藏。检查不代表每个视频都能流畅播放，也不保证涵盖全部资源。

搜索渠道不需要也不会收到夸克 Cookie。分享有效性检查仅访问夸克官方接口；已连接并启用账号时使用该账号核验，否则匿名核验。Cookie 具有访问账号网盘的高权限，访问自己的网盘、转存和获取播放地址时，只在受保护的应用设置页填写自己的 Cookie 并启用夸克功能；请勿将 Cookie 写进 Compose、环境变量或聊天。凭证仅在服务端加密保存，设置页只返回凭证配置状态，普通配置导出不包含凭证。

有效分享缓存 2 分钟，暂不可核验的结果 30 秒后可重检，不永久删除。重新核验已有分享期间保留其上次已验证的状态，复核失败后移除选项；新分享必须通过检查才显示。全局最多同时检查 2 个分享，每个分享活动检查最多 8 秒、6 次请求，排队最多 30 秒；未完成的检查通过播放器轮询逐步返回。目录过深、分页信息异常或临时访问限制时先隐藏，避免把尚未核验的链接当作可用资源。

海报通过本应用的已登记影片 ID 读取，服务端发送豆瓣要求的固定来源信息，避免浏览器直接请求被 CDN 拒绝。只允许登记的豆瓣图片主机，检查公网 DNS、图片格式和大小，并限制缓存与并发；不提供任意 URL 图片代理。简介优先中文，缺少中文时明确说明，外语原文默认折叠，不虚构翻译或把用户短评当成剧情简介。

## 获取网页登录 Cookie

在 https://pan.quark.cn 登录自己的账号，打开浏览器开发者工具的 Network，刷新或打开一个自己的文件夹，选择文件列表请求（路径含 `/1/clouddrive/file/sort`），从 Headers → Request Headers 复制整段 Cookie 值。支持 `Cookie:` 前缀，保留原请求中的全部 Cookie 对及顺序；不要只复制某一个字段的值、响应的 Set-Cookie、JSON 导出或整组请求头。只在应用设置页粘贴，不发送到聊天中。

本地检查 Cookie 的请求头格式，账号是否有效仍由夸克的配置与个人文件列表接口验证。格式正确不代表已登录；接口拒绝或无法确认账号时不会保存新凭证、转存或删除文件。

## 可选搜索助手

新版三个主部署文件已包含独立的 `quark-browser` 动态网页助手；[docker-compose.nas.yml 一体化部署](README-WEB.md#intel-核显-nas-单文件部署) 还包含 PanSou。只使用原来的单个文件启动和更新，浏览器助手不需要夸克 Cookie。

**已有部署此次需要补充 Compose 服务；只拉新镜像无法创建浏览器助手。** 不要下载新 YAML 覆盖你填写过密码、核显组号和数据卷的文件。在原部署目录执行下面一条命令，把文件名换成你实际使用的单个文件：

```sh
curl -fL -o /tmp/vipvideo-enable-quark-browser.py https://raw.githubusercontent.com/loren1997/vipvideo-web/main/scripts/enable-quark-browser.py && python3 /tmp/vipvideo-enable-quark-browser.py --file docker-compose.nas.yml && docker compose -f docker-compose.nas.yml up -d --pull always web quark-browser
```

需要 Python 3 和 Docker Compose v2。脚本读取 Docker 已展开的现用配置，只添加浏览器服务及连接地址，保留项目名、密码、其他服务、核显映射和数据卷；先生成权限 `0600` 的原文件备份，校验后原子替换。重复运行不再改写文件。现有同名服务或自定义浏览器地址冲突时停止，不覆盖。更新后仍是原来的一个文件，内容改为 Docker 支持的 JSON 格式，环境变量采用当前展开值；配置和备份均含敏感设置，请留在原主机，不要上传。固定旧镜像版本的部署需先选择包含本功能的新版本。

脚本只处理单文件。仍使用多个 `-f`、`COMPOSE_FILE` 或默认自动加载的 `compose.override.*` / `docker-compose.override.*` 的部署应保留全部 GPU / PanSou 等附加文件，先手动合并。以下仅适用于原来就使用这三个文件的部署；按自己的实际文件列表调整，不能省略其中任何一项：

```sh
umask 077
docker compose -f docker-compose.yml -f compose.gpu.yaml -f compose.quark.yaml config --format json > vipvideo-merged.json
docker compose -f vipvideo-merged.json config --quiet
```

合并文件可能包含敏感设置，留在原机。Docker 的规范化输出会保留 Compose 转义，不要再次批量替换美元符号；再次 `config` 后核对密码、命令、环境变量和路径未变化，不能直接覆盖原文件。校验项目名、核显、其他服务及数据卷无误后，对合并文件运行脚本，之后只使用这个合并文件启动。单文件用户无需执行合并步骤。

可用 `docker compose -f docker-compose.nas.yml ps` 检查 `web` 和 `quark-browser`。动态助手只在 Compose 网络监听 `3020`，没有主机端口、应用数据卷、家庭密码、账号 Cookie 或 GPU 权限；根文件系统只读，临时目录随容器重建清空。它使用同一个应用镜像，限制为 0.5 CPU、512 MiB 内存及 256 个进程，不作为播放器启动的依赖。

PanSou 仍可作为额外搜索渠道。未使用一体化文件的部署可按下面方式添加它：

在现有 `docker-compose.yml` 所在目录下载附加文件：

```sh
curl -fL -o compose.quark.yaml https://raw.githubusercontent.com/loren1997/vipvideo-web/main/compose.quark.yaml
docker compose -f docker-compose.yml -f compose.quark.yaml up -d
```

Ubuntu Docker 已启用 Intel GPU 的部署继续使用原 GPU 文件：

```sh
docker compose -f docker-compose.yml -f compose.gpu.yaml -f compose.quark.yaml up -d
```

后续 `pull`、`up`、`ps` 均使用同一组 `-f` 参数。附加文件合并到现有 `web` 服务，保留原文件中的 `APP_PASSWORD`、端口、数据卷和 GPU 配置。

助手只在容器网络监听 `8888`，不发布 NAS 主机端口；应用访问固定 `http://pansou:8888/api/search`。如果设置页保存了其他公网搜索 API，请清空该设置以使用助手；未启用助手且未配置公网 API 时，继续使用网页搜索。不要将 Cookie 发送给搜索服务。

```sh
docker compose -f docker-compose.yml -f compose.quark.yaml ps
docker compose -f docker-compose.yml -f compose.quark.yaml exec -T pansou wget -qO- http://127.0.0.1:8888/api/health
```

使用 GPU 文件时，上述检查命令也加入 `-f compose.gpu.yaml`。健康检查仅证明助手运行，搜索仍依赖外部网站的可达性。

如果影片页提示找不到搜索助手或域名解析失败，先检查 `pansou` 容器是否存在并运行。它与 `web` 必须处于同一个 Compose 网络；一体化部署在原目录执行 `docker compose up -d pansou web` 可恢复缺失的助手。沿用原部署文件及项目名；使用附加文件时保留全部 `-f` 参数。更新时使用 `up -d --pull always web pansou`，避免只更新播放器却留下已删除或停止的助手。

内置助手连接失败后按 10、20、40 秒退避，最长 60 秒；旧版超过一分钟的内置助手暂停会解除，公网接口仍保留较长退避。无资源的错误结果不会继续缓存一分钟；助手恢复后可点影片页的“重试搜索”。“查找更多公开资源”仍只查询公开网页。

PanSou 正常的零结果响应可能只有 `data: { total: 0 }`，应用会继续搜索其他渠道，不再将它误判为接口故障。某个片名的备用关键词耗尽剩余时间，也不会暂停此前已正常响应的接口。升级后会让已配置、被旧逻辑暂停的接口重新尝试一次；后续真实故障仍会退避，避免反复占用 NAS 资源。

搜索全部失败时，影片页会分别显示接口超时、连接失败、HTTP 状态或暂时暂停等固定诊断，不显示账号凭证和上游原始错误。返回零条结果只代表本次查询没有命中，不能据此判断接口已失效；也不能保证存在对应的公开夸克分享。

## 资源与隐私

附加文件使用[官方 PanSou API 镜像](https://github.com/fish2018/pansou)，固定摘要 `sha256:d371fe5caa87794414dd54cda063fcfc456d5013e18b65dbf1f6ca17f6299492`；2026-10-13 匿名核验包含 `linux/amd64` 和 `linux/arm64`，对应上游源码提交 `221665fb2c9279f22af4684ea2d8c0c331eac1cc`。

只启用 `pansearch`、`quark4k`、`quarktv` 三个影视网盘插件与一个影视频道 `Quark_Movies`。按[官方参数说明](https://github.com/fish2018/pansou/blob/main/README.md)限制并发为 2、插件超时为 6 秒、缓存为 32 MiB，并限制容器使用 0.25 CPU / 384 MiB 内存。缓存放在临时内存目录，重启后可重新生成；助手不挂载应用数据卷，不接触夸克账号。

应用搜索传输仅为固定助手地址开放内部 HTTP；其他地址继续检查公网 DNS、协议和重定向。搜索 API 请求不携带 Cookie、Authorization 或 API 密钥，每次请求连同正文最多 8 秒，响应最多 2 MiB。动态浏览器每次创建新的匿名会话，只保留当次公开网站的临时 Cookie，任务结束即关闭，不使用你的家庭登录或夸克账号凭证。

搜索 API 现在自动维护备用池，不需要手动填写多个接口。每天从 PanSou 官方项目公开信息和公开搜索结果发现候选；每 6 小时轮转验证最多 2 个接口，后台按顺序执行。支持 PanSou JSON 及 Pansousuo 的 `q/pan/sort` 查询和 `items/share_url/access_code` 响应。只有实际返回合法夸克分享链接的候选才能成为可用备用，首页或健康接口返回 200 不能代替搜索验证。设置页显示自动备用接口的可用、待验证和暂停数量。

公开接口发现按天轮转中文夸克搜索、公共网盘搜索 API 等查询方向。每天最多读取 4 个目录：2 个官方来源、1 个轮换的 GitHub 部署检索或官方插件接口目录、1 个轮换的公开 RSS 搜索。另加入 `pansou.252035.xyz`、`www.pansousuo.com` 两个公开待验证入口，须在 NAS 实际搜索通过后才启用；它们的可达性和结果数量不能保证。候选需要经过兼容与实际结果验证；不兼容的搜索网站不会被冒充为可用 API。

备用池最多保存 8 个记录，状态存入 SQLite。失效公网接口暂停 15 分钟起、最长 6 小时，后续验证恢复后重新使用。自动发现的接口连续至少 3 次失败，且失败探测横跨至少 24 小时后自动删除；保留最多 8 条、有效期 7 天的退避记录，避免刚删除就反复发现回填。你手填的主接口和固定 PanSou 助手保留。API 搜索最多同时请求 2 个接口，整体预算 8 秒；接口无结果或失败时继续公开网页搜索。较慢查询在后台继续，页面轮询接收迟到的结果，不会重复启动同一检索。未发现可用备用时仍使用主接口和网页兜底，公开接口的数量与稳定性不能保证。自动发现只读取公开信息，不扫描未知端口、不自动配置需要登录或密钥的服务。

优先按完整作品名称及影视源明确提供的别名搜索，不将相近片名当作同一部影片。明确的单片上映年份冲突会排除，合集、连载年份和网页发布日期分别处理。影视源名称中的明确集尾、更新进度、完结和画质尾注会从查询词中清理；“希望2026”等片名本体数字保留。电视剧、动漫先搜索剧名，再在分享文件中匹配所选集数，不把当前集名当作搜索词。

匹配片名的分享进入资源列表；无标题或只有“资源链接”等说明的分享单独列在“片名待确认的公开链接”，仅供外部打开，不自动转存，也不会冠上当前影片名称。结果中子项只写“4K”等质量说明时保留已核对的上层作品名称；先遍历有界结果再限制显示条数，避免前面的无关结果挤掉真正匹配项。搜索候选不代表可自动转存，后续文件仍严格核对作品、年份、季度及集数。快速返回的两个渠道最多多等 150 毫秒合并结果，迟到结果在内存缓存 2 分钟，最多保存 32 个查询；同一分享合并保留提取码。

夸克影院中的“查找更多公开资源”主动查询 Google 与 Bing，绕过已完成的查询缓存，合并新的有效分享，并显示新增数量；进行中的同一查询继续复用，轮询不会重复发起搜索。后续查询在前三页之间轮转，避免反复打开同一批文章。已有分享会重新核验并移除当前不可用的选项，已转存视频的播放和准备状态保留，不自动转存新分享。API 使用 8 秒预算，随后静态网页可使用独立的 3 秒预算；主动查找或快速搜索无匹配时，隔离助手继续读取搜索结果和相关文章。共享查询最长 45 秒，并根据剩余时间为动态 Google 页面及文章读取预留预算。Google 请求优先按日期从新到旧排序（`tbs=sbd:1`），不限定日期范围；文章按可核验的实际发布时间排序，缺少日期的排在后面。每轮最多打开 5 个相关文章，单页正文最多 512 KiB。动态任务单并发按需运行，页面自动检查迟到结果，任务结束关闭浏览器。

每次请求和重定向继续核验协议、公网 DNS 与 IP，拒绝内网、账号凭证转发及子页面导航。Google 的不透明结果跳转仅在可信的同源搜索结果中接受，进入真实文章后重新核验片名及影片年份。文章中的真实超链接和可见文本会与片名、年份和正文区域共同核验，不依赖固定链接位置；导航、相关推荐及其他影片分区不会借用当前片名。只访问公开页面，不绕过登录或验证码。Google 不可达、限流或要求验证时停止该渠道，并保留安全失败原因。

网页查询结合准确片名、豆瓣条目明确提供的别名和上映年份，在现有请求预算内尝试中文、外文查询。相关性检查同时核对结果标题、文章主标题和正文开头，避免站点通用标题挡住相关资源，也不把名称相近的不同影片自动合并。中国区 Bing 的普通网页结果与 RSS 均可提供候选，第一篇文章没有链接时继续检查其他相关文章。部分渠道失败时保留具体的安全失败原因，便于区分渠道不可达与成功查询后无结果。

### quark-auto-save 的资源来源

[quark-auto-save 的搜索入口](https://github.com/Cp0204/quark-auto-save/blob/1c35e969332e03980f60c34fc15b2467370bafb2/app/run.py#L235) 使用 PanSou 和 CloudSaver。PanSou 已在本项目接入，不重复建立同源接口；CloudSaver 的搜索底层会读取公开 Telegram 频道，参见 [公开频道实现](https://github.com/jiangrui1994/CloudSaver/blob/0f110840cf531546d7bbb8bcec94e47b0f7b7a1e/backend/src/services/Searcher.ts#L78)。

本项目直接匿名查询公开的 `Quark_Movies` 频道，与 API 和网页搜索并行，无需部署 CloudSaver、增加容器或填写账号。只按每条帖子自己的主标题、影片年份及官方别名匹配；简介中提到其他影片或“希望”等普通词不会成为匹配证据。夸克链接及提取码在同一帖子内解析，按帖子发布时间从新到旧合并，再经过现有的夸克官方分享及视频目录验证，验证失败的结果不显示。

“查找更多”继续读取该频道较早的帖子，使用 Telegram 的 `before` 分页；主片名和官方别名分别保留临时游标，避免别名搜索反复回到第一页。游标只保存在内存中，最多 32 项、保留 2 分钟；每次最多 3 个请求、总预算 10 秒、单页最多 512 KiB，沿用公开搜索的并发限制、代理及取消机制。频道内容由第三方维护，覆盖有限。旧版 quark-auto-save 的 `s.917788.xyz/task_suggestions` 公共源已被[上游移除](https://github.com/Cp0204/quark-auto-save/commit/1c35e969332e03980f60c34fc15b2467370bafb2)，本次验证不可用，未添加。

搜索结果标题没有写上映年份时，明确匹配片名的 Google 文章仍会被打开；Google 跳转后的实际文章必须再次核对影片及年份，才提取分享链接。每轮先读取最多 5 篇相关文章，并发最多 2、共享 8 秒预算；没有找到分享时，再读取需要 JavaScript 的页面。要求登录或回复才能查看的内容会提示无法匿名读取，不会把搜索摘要中的链接当作文章资源。

有些文章默认展示其他网盘，将夸克资源保存在 Next.js 的公开页面数据中。程序只解析标准 JSON，逐条核对同一个资源对象的网盘类型、有效状态、影片标题、上映年份和规范分享地址；不执行页面脚本，也不将其他影片对象中的标题或年份拼到链接上。提取后仍须经过夸克官方视频目录验证。

Google 返回 HTTP 200 也可能只是要求 JavaScript 的启动页面；配置了隔离助手时，Google 搜索直接交给浏览器，最多使用 20 秒，包含 Chromium 启动时间，避免重复发送静态预读请求。查询保留片名、上映年份、语言及日期排序，去掉额外的网页类型和结果数量筛选；文章仍严格核对影片与年份。遇到验证码立即停止。Linux 镜像在容器内的私有虚拟显示运行普通 Chromium，不会打开主机桌面窗口；任务结束回收浏览器及临时资料。默认未填写搜索接口时也会尝试固定 PanSou 助手及已验证的备用接口；“查找更多”刷新助手结果，同时继续网页查询，轮询不会重复启动检索。未安装助手时明确提示配置缺失。可点击“用浏览器查 Google”手动查看相同日期排序的查询。自动检索仍取决于 NAS 网络和上游限制；需要显式 HTTP 代理时见 [部署中的代理配置](README-WEB.md#nas-直接部署镜像)。

只有页面明确给出的发布时间才用于排序和显示，已知日期按新到旧、无日期保持在末尾；影片上映年份、网页版权年份不作为分享日期。搜索结果显示的日期与页面发布时间可能不同，页面发布时间也不等同于网盘上传时间，因此最终结果自行按已确认的页面日期排序。

2026-10-14 实际核验用户提供的腾讯频道公开帖子：普通安全 HTTP 使用网页请求头即可读取服务端生成的完整正文，`希望2026` 可对应带独立 2026 影片年份的 `2026韩国电影希望Hope` 标题，从真实超链接提取到 1 条夸克分享，并读取页面明确给出的发布时间 `2026-09-13T11:48:46+08:00`，该次无需启动动态浏览器。该结果仅证明这篇公开文章的提取链路，不代表所有文章、分享有效期或实际网盘播放均已验证。

已启用并连接夸克账号时，分享口令和文件目录请求使用该账号 Cookie，仅发送到固定夸克官方 HTTPS 接口，并禁止跟随重定向；公开搜索和浏览器返回数据不包含 Cookie。读取期间切换、断开账号或撤销观看权限会取消旧请求，账号变更会清除旧文件候选。

文件下拉框明确区分“加载中”“读取失败”和“暂无视频”，这些状态都不能转存；读取成功后再选择当前影片或剧集。401 提示重新连接夸克账号，403 表示接口拒绝访问、需到官方页面确认权限或分享状态，429 表示请求过于频繁；这些夸克错误不会退出播放器的家庭登录。分享权限、提取码、平台访问限制或风控不能通过本应用绕过。

本应用创建专用目录后记录返回的目录 ID，并最多查询 3 次确认列表已更新，合计等待 1.5 秒。目录索引更慢时提示稍后重试；重试只读取已登记目录，不重复创建目录或转存，也不认领你原有的同名目录。

Cookie 更新导致账号识别变化时，只有当前网盘完整根列表能确认唯一旧登记目录的 ID、安装随机名称、目录类型及根位置，才重新关联该目录和其中已登记的文件。重新关联保留当日额度历史并复用已转存文件，不移动或删除云端内容。目录被改名、移动、删除，或者只有同名目录但 ID 不符时，先停止操作并显示具体原因。

根目录中确实没有原专用目录时，点击独立详情的“恢复专用目录并重试”，或“资源设置 → 夸克网盘 → 恢复专用目录”。应用创建带随机后缀的新 `VipVideo-…` 目录，保留旧登记、文件及当日已用额度；只向新目录转存和清理其中登记的文件。旧目录中的文件不会自动删除，需在夸克中自行处理。恢复成功后可继续准备所选单集，完成后由你点击播放。重复点击或重启会继续核验同一次创建，不重复建目录；创建尚未反映到目录列表时稍后重试。恢复不需要更换 Compose 文件、清空数据卷或重新填写 Cookie。

独立详情只在你选择文件并点击转存后创建任务，等待期间每 5 秒检查一次，最多 12 次。超出等待范围可手动继续准备，错误会显示具体原因。准备完成只显示播放按钮；搜索、打开海报、换分享和选集均不会自动转存或播放。换文件或离开页面会取消旧任务的页面轮询，不删除已转存文件。

“正在夸克播放”只在视频实际开始播放后显示。取流或兼容播放启动失败时，可重试或返回夸克资源选择，不会把失败标成成功。原文件续播会先检查上游是否真正支持 Range 定位；不支持时停止长时间顺序读取并说明原因，可由你点击“从头兼容播放”，不会自动清零观看进度。

夸克返回多个 HLS 清晰度时，服务器生成受登录保护的自适应主清单，客户端从不高于 1080p 的可用层起播，再按实际网速自动调节；播放器的画质菜单仅列出实际可用的层，也可手选 4K 或恢复自动。只有 MP4 等直链时同样优先选择不高于 1080p 的可用流；没有较低画质时使用官方实际返回的流。会员权限和各清晰度是否已经生成仍由夸克决定。

媒体转发使用有上限的连接池，减少分片反复握手，仍在每次请求和跳转时校验目标地址；拖动进度、离开页面或切换账号时中止旧请求。不会预下载全部清晰度或整部影片。HLS 客户端缓冲有时间与容量限制，避免持续扩大内存占用。原文件回退仍需 NAS 下载原码率内容，实际速度取决于夸克、NAS 出网和设备解码能力，不能保证与官方网页完全一致。

网页优先尝试账号可用的官方播放地址，失败后尝试原文件正常下载地址与 Range 请求。播放、下载接口和媒体请求使用一致的桌面客户端 User-Agent；不改变账号权益。401 登录失效、429 限流或观看权限撤销时立即停止，不继续获取下载地址。两种地址都不可用时提示具体阶段与安全的 HTTP / API 数值码，不显示账号凭证或上游原始错误。

MKV、AVI、TS / M2TS 通过 NAS 的兼容转码播放；原生播放器或 HLS 明确报告解码、编码不兼容时，也自动尝试一次兼容播放。网络或 HTTP 错误不会被当成解码错误，失败不会循环转码。会员权益、画质和速度由夸克返回的接口能力决定，不保证第三方网页不限速。兼容转码沿用项目的核显 / 软件设置与输出限制。

## 外挂字幕

转存选中视频时，同目录及其 `subtitles` / 字幕子目录中匹配的 SRT、VTT、ASS 文件会一并转存；电视剧按季、集匹配，电影目录只有一个视频时也识别“简体”“CHS”等语言命名。每个视频最多关联 8 份字幕，每份最多 2 MiB，不转存其他集视频。已转存视频再次点击准备时可补齐字幕；字幕失败会单独提示，已准备的视频仍可播放。

播放器的“外挂字幕”可选择关联字幕或关闭；“添加字幕文件”也可读取本机字幕，文件留在当前浏览器，不上传 NAS 或夸克。支持 UTF-8、GBK / GB18030、带 BOM 的 UTF-16，ASS 按对白文字显示。兼容续播自动对齐原片时间；切换视频或停止播放后清理字幕。关联字幕的读取需要家庭登录，不向浏览器公开账号 Cookie 或网盘下载直链。

## 转存额度与自动清理

初始状态关闭夸克个人网盘功能和自动清理，按需要在设置页连接账号、启用。独立影院始终要求手动选择和转存，旧版保存的自动转存开关不会触发该流程。默认每日最多 100 次，可在设置页调整为 1–100 次；每日容量预算独立生效，默认合计 3 TB（3,000,000,000,000 字节），单文件最多 100 GiB，同时受每日总额度限制。升级时，旧版默认的 20 GiB 每日容量会一次性提高到 3 TB，其他自定义限额保留；当日已用次数与容量不会清零。不会将搜索结果或整个分享目录全部转存。实际容量和播放速度受你的网盘空间、会员权益、平台接口及网络条件影响。

电视剧与动漫按选中的集名识别 `S01E012`、`EP12`、`Episode12`、`1x12`、`第十二集` / `第一百零二话` 等格式，并核对片名、年份及季度。纯数字文件名只有在目录提供可靠片名等信息时才能匹配。年份、分辨率、帧率、编码和声道数字不会被当作集数；连集、季度冲突、同集多个文件或无法确认季度时要求手动选择，不自动猜下一集。

旧部署保存的 10 次默认值会在本版本首次启动时升级为 100 次；其他已设置的次数保留。此后你在设置页明确选择的次数会持久保存，重启不会再次覆盖。升级不修改账号、自动转存开关、清理设置、每日容量预算或观看记录。

自动清理默认保留 7 天，可调整为 1–365 天或关闭。只有确认已观看完成的、本应用转存登记的视频及其关联字幕才进入清理范围；距最近观看或活动满保留期限，且没有活跃播放租约后，每天检查一次，每轮最多处理 5 个文件，字幕清完后再清视频；容器重启后按上次检查时间继续，到期不会重新等待整天。未看完的视频及你原有的网盘文件不会被这项清理删除。删除后只移除该文件对应的回收站条目，以实际释放网盘容量，不清空其他回收站文件。

凭证使用 AES-256-GCM 加密保存在 SQLite 中，加密密钥为数据卷里的 `/app/data/quark.key`。备份、恢复或迁移时同时保留整个数据卷中的 SQLite 文件和该密钥；仅恢复数据库将无法解密原凭证。密钥与数据库同处一个数据卷，应按原部署说明保护和备份该卷。

## 已验证的范围

海报修复已用真实联网页面验证列表与详情图片实际解码，覆盖豆瓣 CDN 无来源信息返回 418、固定来源信息返回有效 JPEG 的场景；旧收藏在八天后重启或目录缓存淘汰后也可按同 ID 恢复，离开页面会取消图片请求。默认未填搜索 API 的实际 Docker 链路约 4 秒从 PanSou 返回 4 条匹配候选，匿名核验中 3 条分享包含视频，另 1 条不可读或无视频的结果被隐藏。此项没有转存、删除文件或使用个人账号，不代表所有影片都有公开分享。

此前发布的 GitHub Actions 已通过实际 PanSou 容器启动与健康检查、双架构 MP4 / AES-128 HLS / MKV / AVI / MPEG-TS 转码、Compose 启动以及停机备份恢复。新增的原文件续播验证使用合成视频和真实流式 HTTP，覆盖 281 秒定位、尾部 MKV 索引、限速与忽略 Range，以及 HEVC Main10 2160p60 / DTS / EAC3 输入，验证实际输出可解码的 H.264 / AAC。Windows 便携 FFmpeg 与 Linux 镜像中的版本及核显驱动不同，软件测试不能代替 NAS 的 VAAPI 验证。

独立夸克影院已在本地 WSL2 / Docker 的 Linux amd64 环境构建并验收：Node.js 24、镜像内 FFmpeg 5.1.9、非 root、原 Compose 限制、健康检查、PanSou 通信、备份恢复与登录会话保留均通过。Linux 模块 / 接口测试无失败；主机缺少 Chromium 而跳过的渲染组，另在 0.5 CPU / 512 MiB 的真实 Chromium 容器中全部补验。48 组完整无界面页面流程通过，覆盖独立目录、分类与三种排序、匿名查询、手选转存、明确点击播放、更多结果、已存文件续播和手机 / TV 遥控布局。

真实联网容器中，豆瓣 2025 电影目录约 1.3 秒返回 19 张海报，未缓存电视剧详情正确返回 40 集及官方评分；公开网页助手约 9 秒从相关公开文章提取到 2 条匹配夸克候选，其中 1 条有明确发布时间。这仅验证该次公开目录和文章检索，不代表候选分享永久有效。单核、1 GiB 下的五个合成媒体用例覆盖 281 秒续播、限速 / 无 Range 和 4K Main10 / DTS；可定位输入约 2.7–2.9 秒起播，不能作为真实影片吞吐量或会员速度保证。更新脚本已核验密码中的美元符号、核显、卷名、备份和重复执行。WSL 测试内核不支持 swap limit，正式配置仍保留该限制。

开发者可在仓库目录构建本地镜像后执行新增验证；它不连接真实夸克账号，不转存或删除网盘文件，保留生产的 20 秒启动限制：
